Handbuch zur Inbetriebnahme

Welcher Dienst,
welcher Klick

Vier Dienste tragen die Lagerverwaltung: Supabase speichert die Daten, Brevo verschickt die Mails, Cloudflare R2 hält Bilder und große Dateien, GitHub liefert die Seite aus. Dieses Dokument geht jeden Dienst der Reihe nach durch — was du dort anklickst, was du kopierst und wo es hingehört.

Was du vorher brauchst

Konten bei Supabase, Brevo, Cloudflare und GitHub — alle vier hast du. Dazu die Projektdateien (StockControl.dc.html, config.js, supabase-client.js, Ordner supabase/ und .github/) und auf deinem Rechner Node.js sowie die Supabase-CLI (npm install -g supabase). Rechne mit 60–90 Minuten.

1 · Supabase — Datenbank

Dienst: supabase.com

1.1 Projekt anlegen

  1. Auf supabase.com anmelden → New project.
  2. Name frei wählen, z. B. stockcontrol. Region: Frankfurt (eu-central-1) — kurze Wege und EU-Datenhaltung.
  3. Ein Datenbank-Passwort setzen und sicher ablegen. Du brauchst es selten, aber ein Verlust ist lästig.
  4. Projekt erstellen, zwei Minuten warten.

1.2 Schlüssel notieren

Links im Menü Project Settings → API. Drei Werte brauchst du später:

FeldWofür
Project URLkommt in config.js
anon publickommt in config.js — darf öffentlich sein
service_rolebleibt geheim, nur für den Zeitplan in Schritt 2.4

Die Project Ref (der Teil vor .supabase.co) brauchst du für die CLI.

1.3 Schema einspielen

  1. Links SQL Editor → New query.
  2. Die Datei supabase/schema.sql öffnen, gesamten Inhalt kopieren und einfügen.
  3. Run. Erwartet: Success. No rows returned.

Angelegt werden neun Tabellen — companies, profiles, settings, products, movements, events, event_items, invitations, notifications — dazu die Sicherheitsregeln und die Automatik.

Warum keine Firma die Daten einer anderen sieht

Jede Zeile trägt eine company_id. Row Level Security lässt nur Zeilen durch, deren company_id zum angemeldeten Konto passt — im Browser, über die API, in jeder Abfrage. Das ist keine Einstellung in der Oberfläche, sondern eine Regel in der Datenbank: auch ein Fehler in der Anwendung kann sie nicht umgehen.

1.4 Was die Datenbank von allein tut

AuslöserReaktion
Neue RegistrierungFirma und Profil werden angelegt, Person 1 bekommt die Rolle owner
Registrierung mit gültiger Einladung (3 Std.)Person wird der einladenden Firma zugeordnet, Rolle aus der Einladung
Entnahme oder NachfüllungBestand wird fortgeschrieben, Status gesetzt, Person und Zeit protokolliert
Bestand fällt unter MindestbestandEintrag in notifications — Grundlage der Mail
Buchung auf deaktiviertem Produktwird übersprungen: kein Tracking, keine Mail

Die Oberfläche schreibt nur die Bewegung. Fortschreibung und Warnung erledigt die Datenbank — so kann keine Buchung am Protokoll vorbeigehen.

1.5 Prüfung

Links Table Editor öffnen: die neun Tabellen sind da und leer. Bei jeder hinter dem Namen das Schloss-Symbol — RLS ist aktiv.

2 · Brevo — Mailversand

Dienst: brevo.com & supabase.com

2.1 Absenderadresse verifizieren (Brevo)

  1. In Brevo Senders, Domains & Dedicated IPs → Senders → Add a sender.
  2. Adresse eintragen, z. B. lager@deine-domain.de, und über die Bestätigungsmail freischalten.
  3. Besser noch: unter Domains die ganze Domain hinterlegen und die genannten DNS-Einträge (SPF, DKIM) setzen. Dann landen die Mails deutlich seltener im Spam.

Ohne verifizierten Absender verweigert Brevo den Versand — das ist die häufigste Ursache, wenn später keine Mail ankommt.

2.2 Zugangsdaten abholen (Brevo)

Unter SMTP & API findest du zwei Dinge, beide werden gebraucht:

ReiterWofür
SMTP (Login + Schlüssel)Supabase verschickt damit Bestätigungs- und Passwortmails (Schritt 2.3)
API Keys (xkeysib-…)Bestandswarnung, Bestellliste und Einladung (Schritt 2.4)

2.3 Anmeldemails einstellen (Supabase)

  1. Authentication → Providers → Email: Confirm email einschalten.
  2. Authentication → URL Configuration → Site URL: deine künftige Adresse, z. B.
    https://deinname.github.io/stockcontrol/. Steht die falsch, führen die Links im Mail ins Nichts.
  3. Bei Email OTP Expiration bzw. der Linkgültigkeit 900 Sekunden eintragen — die geforderten 15 Minuten.
  4. Project Settings → Authentication → SMTP Settings aktivieren und Brevos SMTP-Daten eintragen:
    Host smtp-relay.brevo.com, Port 587, Benutzername und Passwort aus Schritt 2.2,
    Absender: deine verifizierte Adresse, Absendername StockControl.

2.4 Versandfunktion hochladen (Terminal)

Im Projektordner, DEIN_PROJEKT_REF ersetzen:

supabase login
supabase link --project-ref DEIN_PROJEKT_REF

supabase secrets set \
  BREVO_API_KEY=xkeysib-DEIN_SCHLUESSEL \
  MAIL_FROM=lager@deine-domain.de \
  MAIL_FROM_NAME="StockControl" \
  SERVICE_NAME="StockControl" \
  SITE_URL="https://deinname.github.io/stockcontrol/"

supabase functions deploy send-mail

Der API-Schlüssel liegt damit als Secret auf dem Server und erscheint nie im Browser. Wer die Seite im Quelltext ansieht, findet ihn nicht.

2.5 Zeitplan für Sammelmails (Supabase, SQL Editor)

Steht in den Einstellungen „Sofort", verschickt jeder Aufruf Einzelmails; bei täglich, wöchentlich oder monatlich fasst er alles zu einer Bestellliste zusammen. Ein Zeitplan genügt für alle Fälle:

create extension if not exists pg_cron;
create extension if not exists pg_net;

select cron.schedule('stockcontrol-mails', '*/5 * * * *', $$
  select net.http_post(
    url     := 'https://DEIN_PROJEKT_REF.functions.supabase.co/send-mail',
    headers := '{"Content-Type":"application/json",
                 "Authorization":"Bearer DEIN_SERVICE_ROLE_KEY"}'::jsonb,
    body    := '{"action":"flush"}'::jsonb);
$$);

*/5 * * * * heißt „alle fünf Minuten" — richtig, wenn Sofortmails wirklich sofort kommen sollen. Wer nur Sammelmails nutzt, nimmt 30 7 * * * (täglich 7:30). Uhrzeit, Wochentag und Monatstag stellst du später in der Oberfläche ein.

2.6 Prüfung

In Brevo unter Transactional → Logs erscheinen die Versandversuche. Nach der ersten Registrierung muss dort die Bestätigungsmail stehen.

3 · Cloudflare R2 — Bilder und große Dateien

Dienst: dash.cloudflare.com

Produktbilder, PDFs und Excel-Dateien gehören nicht in die Datenbank. Sie liegen in R2 — in einem privaten Bucket mit einem eigenen Ordner pro Firma; in Postgres steht nur der Dateiname (products.bild_url).

3.1 Bucket anlegen

Cloudflare-Dashboard → R2 → Create bucket, Name z. B. stockcontrol, Location Automatic. Die Account ID steht rechts in der R2-Übersicht — notieren.

3.2 Privat lassen — nur nachsehen

Im Bucket Settings → Public access prüfen: R2.dev subdomain steht auf Disabled, keine Custom Domain verbunden. So ist ein neuer Bucket voreingestellt — hier ist nichts zu tun.

Öffentlich hieße: wer die Adresse kennt, sieht das Bild ohne Anmeldung. Da jede Firma nur ihre eigenen Sachen sehen soll, bleibt die Ablage geschlossen. Bilder werden über kurzlebige signierte Adressen geladen, die die Funktion aus 3.5 nur für die eigene Firma ausstellt.

3.3 API-Token erzeugen

  1. R2 → Manage R2 API Tokens → Create API token.
  2. Berechtigung Object Read & Write, eingeschränkt auf deinen Bucket.
  3. Access Key ID und Secret Access Key sofort kopieren — das Secret zeigt Cloudflare nur einmal.

3.4 CORS erlauben

Im Bucket Settings → CORS policy, damit der Browser direkt hochladen darf. Deine Pages-Adresse eintragen:

[{
  "AllowedOrigins": ["https://deinname.github.io"],
  "AllowedMethods": ["PUT", "GET"],
  "AllowedHeaders": ["content-type"],
  "MaxAgeSeconds": 3600
}]

Fehlt dieser Eintrag, schlägt jeder Upload mit einem CORS-Fehler in der Browserkonsole fehl.

3.5 Upload-Funktion hochladen (Terminal)

supabase secrets set \
  R2_ACCOUNT_ID=deine_account_id \
  R2_ACCESS_KEY_ID=dein_access_key \
  R2_SECRET_ACCESS_KEY=dein_secret \
  R2_BUCKET=stockcontrol

supabase functions deploy upload-url
Wie ein Upload abläuft

Die Oberfläche fragt die Funktion nach einer Adresse. Die prüft Anmeldung und Upload-Recht, baut den Pfad <company_id>/product/<zeit>-<name> und signiert eine PUT-Adresse, die 10 Minuten gültig ist. Damit lädt der Browser die Datei direkt zu Cloudflare — sie läuft nie über Supabase. Die R2-Schlüssel verlassen den Server nicht, und weil die company_id im Pfad steckt, kann keine Firma in den Ordner einer anderen schreiben.

Ansehen läuft genauso: Dieselbe Funktion beantwortet die Frage „zeig mir dieses Bild". Sie vergleicht die company_id im Dateinamen mit der des angemeldeten Kontos — stimmt sie nicht, gibt es keine Adresse und damit kein Bild. Stimmt sie, kommt eine signierte Leseadresse für eine Stunde zurück. In products.bild_url steht nur der Dateiname, nie eine offene Adresse. Ein weitergegebener Link ist nach einer Stunde wertlos.

Erlaubt sind JPEG, PNG, WebP, AVIF, PDF, XLSX und CSV bis 15 MB. Anpassen in supabase/functions/upload-url/index.ts (Listen ALLOWED und MAX_BYTES).

4 · GitHub — die Seite ausliefern

Dienst: github.com

4.1 Zugangsdaten eintragen

config.js öffnen und die vier Werte setzen. Das ist die einzige Datei, die du anfassen musst:

export const SERVICE_NAME = "StockControl";
export const SUPABASE_URL = "https://xxxx.supabase.co";
export const SUPABASE_ANON_KEY = "eyJhbGciOi...";

SERVICE_NAME ist der Name des Dienstes — er wird überall in der Oberfläche und in den Mails übernommen. Ändere ihn hier, und er ändert sich an jeder Stelle.

Der Anon-Key darf öffentlich sein: er liest ohne Anmeldung nichts, dafür sorgt Row Level Security. Eine R2-Adresse steht hier bewusst nicht — der Bucket ist privat. Der service_role-Key, der Brevo-Schlüssel und die R2-Zugangsdaten gehören niemals in diese Datei; sie liegen als Secrets in Supabase.

4.2 Repository und Pages

  1. Auf GitHub ein Repository anlegen (privat ist möglich, Pages funktioniert trotzdem) und die Projektdateien pushen.
  2. Settings → Pages → Source auf GitHub Actions stellen. Der Workflow .github/workflows/deploy.yml liegt bereits im Projekt und veröffentlicht bei jedem Push auf main.
  3. Unter Actions läuft der erste Durchlauf; nach etwa einer Minute steht die Adresse oben in Settings → Pages.

Der Workflow legt automatisch eine index.html an, die auf die Anwendung weiterleitet, sowie eine .nojekyll, damit alle Dateien unverändert ausgeliefert werden.

4.3 Eigene Domain (optional)

Settings → Pages → Custom domain setzen, beim Domain-Anbieter einen CNAME auf deinname.github.io legen. Danach die neue Adresse an drei Stellen nachtragen: Supabase Site URL, das Secret SITE_URL, die R2-CORS-Policy.

5 · Erster Durchlauf

Zum Abschluss

  1. Seite öffnen → Registrieren. Firmenname, E-Mail, Passwort (mindestens 10 Zeichen, Groß- und Kleinbuchstabe, Zahl, Sonderzeichen).
  2. Bestätigungsmail abrufen und den Link binnen 15 Minuten anklicken. Kommt keine Mail: Brevo-Logs prüfen und Schritt 2.1 kontrollieren.
  3. Anmelden. In den Einstellungen zeigt „Datenquelle" jetzt Supabase statt Demo-Daten. Erscheint weiter „Demo-Daten", ist config.js nicht ausgefüllt oder nicht veröffentlicht.
  4. Unter Produkt anlegen einen Artikel speichern; er muss in Supabase im Table Editor auftauchen.
  5. Im Produktdetail ein Bild hochladen — die Datei landet in R2, in der Zeile steht die URL.
  6. Mindestbestand über den Istbestand setzen und eine Entnahme buchen: die Warnmail geht an die verantwortliche Person, Stellvertretungen im CC (einstellbar in den Einstellungen).
  7. Unter Team & Rechte jemanden aus dem Team einladen — die Einladung gilt 3 Stunden.

6 · Betrieb

Rollen und Rechte

Die Rolle ist nur die Vorlage. Einzelne Rechte liegen pro Person in profiles.permissions und überschreiben sie — einzustellen unter Team & Rechte → Feinrechte. Das Recht upload steuert, wer Dateien nach R2 schicken darf.

Kosten

Alle vier Dienste haben ein kostenloses Kontingent, das für ein mittleres Lager reicht. Supabase begrenzt Datenbankgröße und aktive Nutzung, Brevo die Zahl der Mails pro Tag, R2 den Speicher — aber nicht den Datenverkehr nach außen, weshalb Produktbilder günstig bleiben. GitHub Pages ist für öffentliche Repositories kostenlos.

Was du regelmäßig prüfen solltest

  • Monatlich: Team-Liste durchsehen — ausgeschiedene Personen sperren oder entfernen.
  • Vierteljährlich: Brevo-Logs auf Zustellprobleme, R2-Speicherverbrauch.
  • Bei Personalwechsel: Verantwortlichkeiten der Produkte umhängen, sonst gehen Warnmails an ein verwaistes Postfach.
